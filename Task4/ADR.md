### <a name="_qmphm5d6rvi3"></a>**Решение**

Диаграмма контекста в [icepannel](https://s.icepanel.io/eNwnlIk1evcv5k/Ql7U) или локально в [файле](./C4_context.png)
Диаграмм контейнеров в [icepannel](https://s.icepanel.io/eNwnlIk1evcv5k/PWF9) или локально в [файле](./C4_container.png)

Сервис обработки ставок позволяет загружать в него данные из XLS-файлов, получать информацию по загруженным ставкам, вносить точечные изменения.
Доступ к сервису из внутреннего контура будет производиться через админку, которая интегрирована с keycloack для использования RBAC-разграничений:
менеджеры депозитов имеют доступы на запись и чтение, сотрудники колл-центра могут только просматривать данные.
При загрузке/обновлении данных ставится таска на выгрузку данных (запись в БД, таблица jobs), за тасками следит воркер выгрузки данных, который асинхронно формирует
 XLS-файл и выгружает его в партнёрский колл-центр по SFTP-протоколу.
Т.к. ставки могут меняться не каждый день, то каждую ночь в начале дня срабатывает крон, который выгружает последние загруженные данные. Это позволит
сотрудникам партнёрского колл-центра не искать последний загруженный файл.

В качестве баз данных можно выбрать MS SQL, т.к. у команды уже есть опыт её использования. Бэк можно пилить на ASP.NET Core также из-за имеющейся у команды 
интернет-банка экспертизы в C# и ASP.NET.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

Для асинхронной выгрузки файлов можно использовать Kafka, тогда воркер выгрузки данных можно будет вынести в отдельный микросервис.
Крон выгрузки данных можно не делать, тогда сотрудникам партнёрского колл-центра нужно будет смотреть на последний созданный файл.
Можно продавить переход партнёрского колл-центра с работы с файлами на API, что позволит избавиться от воркера и крона выгрузки данных.

**Недостатки, ограничения, риски**

Партнёрский колл-центр точно не знает актуальные у них ставки или нет, т.к. при выгрузке наши системы могли упасть и она фактически не выполнилась.
Всё использование взаимодействия по API предпочтительней чем через файлы.
